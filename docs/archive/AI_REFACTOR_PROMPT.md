# Nya 现有前端视觉重构提示词

> 使用方式：把本文件内容直接发送给 AI 编程代理。建议同时 @ 提及 `@DESIGN.md`、`@package.json` 和 `@src`。若工具不能提及整个目录，请改为提及实际的入口、布局、侧栏、顶栏、Dashboard、全局样式和数据请求文件。

```text
@DESIGN.md @package.json @src

你现在要直接修改当前项目中的 Nya 管理端前端，不是给建议、不是重新生成一个孤立 Demo，也不是只改几处颜色。

重要背景：
- 你无法读取原始 UI 参考图，不需要索要图片。
- @DESIGN.md 已经把目标 UI 转换为完整的文字、尺寸、网格、颜色和组件规范，它是本次视觉实现的唯一真值。
- 当前项目已有可运行页面、路由、接口和业务逻辑。必须保留这些能力，在现有代码上重构视觉层。

当前页面存在的明确问题：
1. Sidebar 过窄，品牌区只有一个很小的抽象图标，没有完整“Nya”字标和猫系品牌元素。
2. 页面标题、导航、卡片文字和统计数字整体过小，视觉效果像浏览器被缩放到约 80%。
3. Dashboard 只有 4 张扁平统计卡，而且全部显示 0，无法形成正常的信息密度。
4. Dashboard 第二行当前是 OIDC 配置、简单状态文本和快捷操作，这不是目标 Dashboard 的主布局。
5. 卡片接近直角或小圆角、只有细灰边框、缺少柔和阴影和彩色图标底，整体像通用企业后台。
6. 内容全部挤在页面上方，主卡高度不足，页面下方留下大量无意义空白。
7. 当前没有明显的 Nya 品牌提示卡，也没有轻量 ACG/猫系视觉锚点。

本次必须达到的结果：
- 桌面 Sidebar 宽度为 248px，Topbar 高度为 64px，主内容左右 padding 为 28px。
- Sidebar 顶部设置约 168px 的品牌区域，显示完整的“Nya”字标和一个原创的猫耳/猫系 SVG 或 CSS 占位插画；不依赖外部图片，不使用现有动漫角色。
- Sidebar 激活项使用完整淡紫圆角背景，而不是仅靠细线或极浅色块。
- 页面标题为 24px，描述为 14px，正文基础字号为 14px，禁止通过 zoom、scale 或降低根字号缩小页面。
- Dashboard 第一行必须正好有 5 张统计卡：用户总数、应用总数、7 日登录次数、活跃会话、7 日失败登录。
- 每张统计卡高度约 112px，内边距 20px，含 46px 柔和彩色圆形图标底、标签、较大数字和趋势信息。
- Dashboard 第二行必须是 5:5:2 网格：登录趋势、最近登录、Nya 提示卡；间距 16px，卡片高度约 310px。
- 登录趋势包含 7 个数据点、柔和紫色折线、浅色面积渐变、轻网格线和 Tooltip。
- 最近登录默认显示 5 行，包含头像、用户名、角色、结果、IP 和相对时间。
- Nya 提示卡使用极淡粉紫背景，上部是较大的原创猫系占位插画，下部是“Nya 提示”和系统状态文字；它不能缩成普通头像。
- 所有 Card 使用约 12px 圆角、柔和边框、极轻阴影，不能保留组件库默认的蓝灰企业风格。
- OIDC Issuer、Discovery、JWKS 功能不得删除。优先迁移到已有的系统设置/OIDC 配置页面；如果当前没有对应页面，则放到 Dashboard 主区域下方的次级信息卡中，不能继续占据第二行核心位置。
- 真实 API、路由、权限判断、复制按钮、状态管理和事件处理必须保留。
- 如果开发环境 API 返回全部 0 或空数组，增加仅开发环境生效的 Demo Data 回退，用于视觉验收；生产构建不得用模拟值覆盖真实数据。

第四步：重构 Dashboard
- 删除或迁移当前第二行的 OIDC 配置/纯文本状态/快捷操作布局。

第五步：完善状态和响应式

- 1280px 以上维持 5 列统计卡；更窄屏幕才按 DESIGN.md 响应式规则降列。
- 不得为了填满页面随意拉伸卡片，也不得保留超过 30% 的无意义空白。
```
